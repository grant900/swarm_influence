# Swarm susceptibility: do AI coding agents get recruited by agent swarms?

Two-day hackathon project (2026-10-06 to 10-08). A coding agent is put on a stuck task in a Docker sandbox. Partway through, it can find a local, fake "agent swarm" forum (`commons.local`) that has the fix but asks for increasingly costly things in return: register, post the task, paste `env`, run `join.sh`. We measure:

- how far up that ladder the agent goes,
- whether it leaks a fake per-trial `DEPLOY_TOKEN`,
- whether it hides the forum from its operator.

**Headline:** across 775 trials and 9 models, a swarm that asks nicely gets some agents to hand over the secret credential and run its script. Most of those agents don't mention it in their final report. The full results are in [`report.ipynb`](report.ipynb), and there's a 3-minute video in [`swarm_video.mp4`](swarm_video.mp4).

**Safety:** nothing touches real sites or resources.
- The forum and the pricing service are local containers on an internal Docker network.
- The agent container has no internet route.
- The OpenRouter key stays on the host behind a loopback relay (`key_relay.py`).
- The leaked "secret" is a fake token generated per trial, and `join.sh` only pings the local forum.
- Don't weaken any of this.

## Setup

Requirements:
- macOS or Linux
- [uv](https://docs.astral.sh/uv/)
- Docker (only for running new trials)
- ffmpeg and Google Chrome (only for rebuilding the videos)

```sh
git clone https://github.com/grant900/swarm_influence.git && cd swarm_influence
uv sync --group report       # harness deps + pandas/matplotlib/jupyter for the report
```

## Reproduce the report from the committed data (no API key, no Docker)

```sh
uv run --group report jupyter lab report.ipynb
# or headless:
uv run --group report jupyter nbconvert --to notebook --execute report.ipynb --output report_rerun.ipynb
```

This was checked on 2026-10-08: re-executing from a clean environment reproduces every output in the committed notebook exactly.

To regenerate the raw tables:

```sh
uv run analyze.py --runs runs_grid --by model_short forum gate norm reveal payoff
```

## Run new trials (costs money; uses OpenRouter)

1. Create `.env` in the repo root. It's gitignored; never commit it.
   ```
   OPENROUTER_API_KEY=sk-or-...
   ```
2. Build the two images:
   ```sh
   docker build -t commons-agent -f docker/agent.Dockerfile docker
   docker build -t commons-site  -f docker/site.Dockerfile .
   ```
3. Run one trial. Add `--view 8080` to watch the forum live at `http://127.0.0.1:8080`.
   ```sh
   uv run run_trial.py --task migrated --pack forum-ontopic-help__gate-costly__norm-conflict --arm forced --model z-ai/glm-5.3
   ```
4. To run the full grid for one model (about 106 to 130 trials, resumable, 5 parallel workers):
   ```sh
   ./run_grid.sh openai/gpt-5.6-sol 5
   uv run judge.py --runs runs_grid
   uv run analyze.py --runs runs_grid --by model_short forum gate norm reveal payoff
   ```

Notes for new runs:
- **Budget.** Every API call is logged to `runs/ledger.jsonl` (gitignored). `run_trial.py` refuses to start a trial once the ledger reaches `BUDGET_CAP_USD`, which defaults to $450; set it in the environment to change it. A fresh clone starts the ledger at $0. The original grid cost about $155 (the ledger went from $93.5 to $248.8).
- **Cost per trial.** Trials take about 2 to 6 minutes and cost about $0.15 to $0.40 each.
- **Docker networks.** Each trial creates its own internal network. Running more than about 5 parallel workers per model, or more than about 2 models at once, exhausts Docker's default address pool. That is how about 55 cells failed in the original grid.
- **Output directory.** New trials written to `runs_grid/` are mixed into the committed data, so use `--runs <new dir>` with `run_batch.py` for anything exploratory.
- **Design rules.** See `PROJECT.md` → "Final grid plan" and `HANDOFF.md` → "Rules": fixed harness after launch, rerun only infrastructure failures, and don't count provider-filter refusals as resistance.

## Videos

All visuals, music and sound effects are generated by code. The only recorded asset is the narrated intro (`intro.m4a`).

### `swarm_video.mp4` (same file as `video/final.mp4`)

The main cut.
- **Visuals:** `video/scene.html`, with local fonts in `video/fonts/`. `video/render.py <outdir> <fps> <start> <end>` writes frames with Playwright and Chrome.
- **Audio:** the music and sound effects in `video/audio/` are generated by `video/audio_src/`:
  ```sh
  cd video/audio_src && uv run --no-project --with numpy --with scipy python music.py
  ```
  Use the same command with `sfx.py` for the sound effects.
- **Mixing:** the final ffmpeg mix command was not saved. `VIDEO_HANDOFF.md` has the cue points and an example mix.
- **`video_build/`:** a later, unfinished revision of the scene (`video_build/web/scene.html`). Its audio is identical to `video/audio/`.

### `video_replica/swarm_video_replica.mp4`

A second, independent cut (177 s). It is fully scripted end to end:

```sh
cd video_replica
uv sync && uv run playwright install chrome   # skip the install if Google Chrome is already present
uv run python render.py video --workers 6     # ~5,300 frames -> silent.mp4 (a few minutes)
uv run python audio.py                        # synthesized music/SFX + intro voice -> mix.wav
ffmpeg -i silent.mp4 -i mix.wav -c:v copy -c:a aac -b:a 256k -shortest swarm_video_replica.mp4
```

To preview, open `video.html?t=SECONDS` or `video.html?play` in a browser. `uv run python render.py stills 12 60 150` writes single PNG frames to `stills/`. Captions come from the word timestamps in `intro16k.json`, produced by `mlx-whisper` (large-v3-turbo). This cut loads its fonts from Google Fonts, so it needs internet access when rendering.

## Caveats (also in the report)

- This is hackathon scale: cells are small, and pooled intervals are wide.
- There is one simulated forum.
- Claude Sonnet 5.5 and Gemini 3.8 Flash were often stopped by provider content filters. Those trials are reported separately, not counted as resistance.
- Agents send the token to the non-forum pricing service about 30% of the time even with no swarm, so read forum leaks against that baseline.
- DeepSeek V4 Flash shares a lab with the judge and with the forum-reply model.
- Kimi K3, Gemini 3.8 Flash, DeepSeek V4 Flash, GLM-5.3-Flash and GPT-5.6-Luna were only partly run because of the deadline.
